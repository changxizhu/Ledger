为什么一周会有多个目录 每次 collect 都在周目录下建立不可覆盖的 timestamped run，用于区分首次采集、补齐来源、重新分析和最终定稿。run.json 是该次运行的文件索引，旧 run 默认保留用于审计；周目录根部只保留当前定稿的 HTML 周报。

运行边界

Python 已实现本地同步、采集、direct 只读刷新、账号核验、评分和文件输出。MCP 读取、用户确认和所有外部回写由 Codex 主会话完成。Subagents 不能访问 connectors、凭据或修改文件。

身份、账号与权限边界

一个私有 profile 关联同一人的多个账号，但每个外部服务仍独立授权。

One person稳定的 person_id
Many aliasesGit 姓名、邮箱与服务 ID
Separate auth每个服务独立授权与核验
Approval gate外部写入只由主协调器执行

配置边界

ledger.toml 保存身份断言、路径、白名单和非秘密引用；它不是登录系统，也不授予任何外部权限。

可以进入 Ledger

  • 稳定的 identity.person_id
  • 不同电脑或账号使用的 Git 姓名与邮箱别名
  • 非秘密的 Linear user ID 与 Calendar ID
  • 仓库路径白名单、快照路径和 expected account
  • env: 或 keychain: 凭据引用

不能进入 Ledger

  • OAuth access token 或 refresh token 的原始值
  • API key、密码、cookie 或 session 文件
  • 从 Linear、Google、GitHub、Codex 或 Claude 复制的凭据
  • 公开仓库中的原始对话、笔记正文或机器路径

连接模式

MCP 适合交互式运行；direct 适合无人值守读取。两者生成同一种周快照，后续脚本和子代理不接触服务凭据。

模式凭据位置账号核验允许的行为
MCPCodex connector store建议配置 expected_user，快照包含 account主协调器读取；用户批准后可写入
Direct环境变量或 macOS Keychainexpected_user 必填，不匹配则停止只读 API，并保存最小化私有快照
Git系统 credential manager 或 SSH agent通过 author aliases 归一身份fetch；只可安全 fast-forward，不自动 push
Interactions本机 transcript + 私有 Google Drive每台设备使用唯一 device_id脱敏增量导出；不上传原始配置目录

原始证据止于 .ledger/。MCP 凭据止于 Codex；direct 凭据止于环境变量或 macOS Keychain。Subagents 只读。公开导出必须是独立、显式且经过验证的动作。

字段职责

采集端与主电脑可以共用同一种配置格式，但只做导出的设备不需要仓库、外部连接器或评分设置。

[identity]
把不同 Git 作者别名和服务 ID 归一为一个人；不是认证信息。
[[repositories]]
声明本机仓库、允许路径、是否读取工作区，以及远端同步要求。
[[interaction_sources]]
主电脑读取 Google Drive 中的标准 Ledger JSONL；路径可以递归匹配多台设备。
[interaction_export]
当前设备的唯一 device_id、本地 Drive 根目录、增量游标和来源选择。
[weekly_index]
四项权重必须非负且合计为 1。
[integrations.*]
启用状态、MCP/direct 模式、快照路径和非秘密凭据引用。
[public_export]
控制匿名摘要是否保留私有主题名；默认不保留。

副电脑的互动导出

所有电脑写入同一个私有 Google Drive 逻辑目录，但各自使用本机挂载路径和不同 device_id。每次运行创建 output_dir/device_id/provider/date--run-id.jsonl immutable batch，避免要求 Google Drive、GVFS 等同步文件系统支持 append、locking 或 chmod；重试时会按 event_id 跳过已存在的记录。副电脑无需保存完整 Ledger 代码。

一次安装与配置

Install and setup
gh auth login
download_dir="$(mktemp -d)"
gh release download exporter-v0.1.1 --repo changxizhu/Ledger \
  --pattern "ledger_exporter-0.1.1-py3-none-any.whl" \
  --dir "$download_dir"
pipx install --force "$download_dir/ledger_exporter-0.1.1-py3-none-any.whl"
ledger-export setup

运行与检查

Run and status
ledger-export run
ledger-export status
隐私说明 Ledger 仓库是 private，因此副电脑先用 GitHub CLI 登录，再只下载 release wheel。默认导出消息正文并在写入前过滤常见凭据形式。--metadata-only 只保留 hash 和计数。Google Drive 目录仍属于私有对话证据，不能公开共享。

每日任务

增量游标只保存在本机。安装命令会在 macOS 创建 LaunchAgent、在 Linux 创建 systemd user timer、在 Windows 创建 Task Scheduler 任务，默认每天 23:30 运行。

Install daily export
ledger-export schedule install

# Optional custom time
ledger-export schedule install --hour 22 --minute 0
Inspect or remove
ledger-export status
ledger-export schedule remove

定时器只调用轻量 exporter；完整周分析仍只在主电脑执行。

最短运行路径

主电脑运行完整周复盘；副电脑只负责每天导出互动。两者通过私有 Google Drive 目录交换标准 JSONL，不需要互相远程连接。

1. 主电脑：安装并验证

克隆后，先按“配置”页创建 ignored 的 ledger.toml，再执行验证并打开 Ledger 作为 Codex project。

Main computer
git clone https://github.com/changxizhu/Ledger.git
cd Ledger
python3 -m pip install -r requirements.txt
After ledger.toml exists
python3 scripts/validate_config.py --config ledger.toml

首次打开项目后重启一次 Codex 会话，使项目配置、skills 和 subagent roles 生效。

2. 主电脑：在 Codex 中运行

Codex dialog
$weekly-ledger-review Review 2026-W34

Codex 生成 evidence-review.md 后暂停；核验表格和 Git patch，再批准继续分析、评分和生成 HTML 报告。

3. 副电脑：一次配置，之后每日自动导出

Secondary computer

运行前检查

这些命令只检查配置、仓库同步状态和跨设备互动覆盖，不会启动主题分析。

Preflight
python3 scripts/validate_config.py --config ledger.toml
python3 scripts/sync_repositories.py --config ledger.toml
python3 scripts/collect_interactions.py inspect \
  --config ledger.toml --week YYYY-Www
python3 -m unittest discover -s tests -v

只有干净且 strictly behind 的仓库才可对同步命令增加 --apply。脚本不会 stash、reset、push 或处理 divergence。

每周复盘

在 Codex 对话框调用 $weekly-ledger-review 并给出 ISO week。Evidence 核验和外部写入是两个独立的人工确认点。

MCP 模式

主协调器先从已授权的 Linear 和 Calendar 读取精确的周一到周一区间，并把批准的最小快照保存到 .ledger/inbox/。

Collect
python3 .agents/skills/weekly-ledger-review/scripts/run_weekly.py collect \
  --config ledger.toml --week YYYY-Www --fetch

Direct 模式

只读 adapter 在运行时解析外部凭据引用、核验 expected_user，并保存与 MCP 相同格式的快照。

Refresh and collect
python3 .agents/skills/weekly-ledger-review/scripts/run_weekly.py collect \
  --config ledger.toml --week YYYY-Www --fetch --refresh-direct
Evidence gate collect 生成 evidence-review.md 后必须暂停。用户可展开 Git patch 核对具体改动；只有确认来源、commit、工作区、互动、Linear 和 Calendar 证据后，才进入主题分析。
Finalize after reviewed weekly-input.json exists
python3 .agents/skills/weekly-ledger-review/scripts/run_weekly.py finalize \
  --config ledger.toml --run-dir RUN

一次运行的原始证据和中间结果保存在 .ledger/runs/YYYY-Www/TIMESTAMP/；最终可读报告保存在同一周目录下的 YYYY-MM-week-N.html。

月度汇总

同一周只取最新的 finalized run，汇总月均指数、主题趋势和重复延期，供长期目标复盘。

Aggregate month
python3 .agents/skills/monthly-ledger-review/scripts/aggregate_month.py \
  --month YYYY-MM --runs-dir .ledger/runs \
  --output .ledger/months/YYYY-MM.json

状态处理

缺失来源是 unknown，不是零进度。同步和连接器异常必须在 Evidence gate 中显式接受或修复。

状态含义处理
synced + clean本地与 upstream 一致，工作区干净可直接采集
synced + dirty远端一致，但有本地未提交证据保留并在 Evidence gate 核验
behind + clean远端有新提交可人工确认后用 --apply fast-forward
ahead本地有未推送提交用户决定是否 push
diverged本地与远端历史分叉停止自动同步，用户处理
source unavailable快照、互动或仓库不可读报告 unknown；必需来源会阻止严格定稿

展示边界

当前私有周报是主要结果；本 Handbook 只解释系统，不读取 .ledger/。未来公开 Dashboard 只能接收经过验证的匿名摘要。

YYYY-MM-week-N.html
放在 ISO 周目录根部、可离线打开的私有页面；N 表示该周周一是当月第几个周一。页面展示主题、任务、分数、证据引用、来源覆盖和结构化反思。
months/YYYY-MM.json
跨周平均、主题趋势和重复延期。
public-week.json
分数、匿名主题进度和计数；未来公开 Dashboard 的唯一输入。
